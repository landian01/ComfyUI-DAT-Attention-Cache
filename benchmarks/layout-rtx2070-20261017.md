# DAT FP32 布局转换：RTX 2070 完整节点对照

2026-10-17，插件 1.2.0，Windows，RTX 2070 / SM 7.5，Python 3.13.16，
PyTorch 2.14.1+cu130 / CUDA 13.0，Spandrel 0.4.2，ComfyUI 0.41.1。
仅使用 2070；通过 `CUDA_VISIBLE_DEVICES` 绑定物理 GPU UUID，进程内只允许一张可见显卡。

## 结果

完整 `ImageUpscaleWithModel.execute`：`4x-UltraSharpV2`，输入 1920×960，输出 7680×3840。
两种模式均保留原有蒙版缓存、使用 PyTorch 蒙版生成、保留 FP32；只切换 DAT 的布局拷贝。
计入全部分块推理、传输和拼接，排除模型/图片加载、GPU 冷却及 PNG 编码。

- 四组对照全部变快；中位数加速比 1.469×。
- 原布局范围 54.096–61.685 秒；加速布局 36.675–42.652 秒。
- 8 次正式输出及两次预热输出均逐位相同，最大绝对误差 0，输出全部有限。
- 两种模式峰值已分配显存均为 4.446 GiB。
- 每次正常结束缓存均清空；异常清理由回归测试覆盖。
- 全局 `torch.Tensor.contiguous` 未改写；四个 DAT 方法以外仍使用原实现。

## 温控与边界

初次连续执行时，2070 出现明显的热漂移，因此该批记录未用作发布数字。
正式测试两种模式各运行一次完整预热；之后按 A/B、B/A、A/B、B/A 顺序执行四组对照。
每次运行前至少空闲 30 秒，且 GPU 核心温度不高于 60°C；冷却时间不计入节点耗时。
每秒采样选定显卡的温度、SM 频率、利用率和驱动温度降频状态。

**即使从低温开始，这张 2070 在单次长任务内仍触发温度降频。** 因此这些数字代表该卡当前散热状态下
的实际节点收益，不能视为无降频条件下的硬件性能结论。各轮温度和降频采样统计保留在 JSON，
修复散热后需要重新测量绝对速度和加速比例。本轮没有调整风扇、功率或时钟设置。

5080 未参与本轮验证；其他显卡及模型不承诺相同收益。测试节点在独立进程运行，
不操作生产 ComfyUI 队列，不重启服务。CPU、系统内存和机箱散热仍是共享资源。

## 数值和回归

布局函数覆盖二维/单批次三维、切片偏移、跨列步长、默认/非默认 CUDA 流及并发线程。
训练、autograd、CPU、非 FP32、不支持的布局和 CUDA Graph 捕获使用 PyTorch。
有限 FP32 测试值（包含正负零和次正规数）位模式一致；Inf/NaN 位置保留，cuBLAS 可能规范化 NaN 载荷。
源码不匹配或已有其他方法包装时，布局补丁整体跳过；蒙版缓存继续工作。

最终本地完整回归：40 项中 39 项通过，1 项可选旧蒙版原生内核测试跳过；
该蒙版内核未针对 2070 重新编译。真实 ComfyUI 节点成功/异常清理测试通过。
compute-sanitizer memcheck 下 13 项布局测试全部通过，报告 `ERROR SUMMARY: 0 errors`。
GitHub CPU CI 另行覆盖 Python 3.11 / 3.13，不能证明 GPU 性能。
此处不重复使用旧的 RTX 5080 蒙版内核测速数字。

## 复现

在已安装 ComfyUI、模型和图片的 Windows 环境中，使用 ComfyUI 自己的 Python：

```powershell
$env:CUDA_VISIBLE_DEVICES = '<所选显卡的完整 GPU UUID>'
python benchmarks/benchmark_layout.py --comfyui 'D:/ComfyUI/ComfyUI' --model '4x-UltraSharpV2.safetensors' --image 'D:/images/test.png' --output 'D:/results/layout.json' --gpu-uuid $env:CUDA_VISIBLE_DEVICES --gpu-name '2070' --pairs 4
```

图片和权重不包含在仓库中；公开记录只含模型名称、尺寸、时间和验证结果。
机器可读结果：[`layout-rtx2070-20261017.json`](layout-rtx2070-20261017.json)。
